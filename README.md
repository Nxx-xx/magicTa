# 塔境 · 方格地图原型 / 肉鸽魔塔 V0.1

**当前默认入口已改为两层可往返的方格地图原型。** 原来的十层卡片模式仍保留，在地图原型菜单中点击“打开旧版十层卡片原型”即可进入，两种模式使用独立存档。

地图设计见 [`docs/MAP_DESIGN.md`](docs/MAP_DESIGN.md)，布局图见 [`docs/map_design.png`](docs/map_design.png)。地图源码入口为 `scenes/map_prototype.tscn`。

## 新版地图原型

- 两层都是 11×11 格；一层教学主路 / 钥匙门 / 强敌奖励支路，二层共同补给 / 主题支路。
- 方向键、WASD、屏幕方向按钮或点击相邻格移动；远处格子只检查、不自动寻路。
- 撞怪先看损失再确认，致死挑战额外确认；开门扣钥匙，物品走到格子自动拾取。
- 首次从一层上楼选择战斗、宝藏、商店主题；已访问楼层只显示普通楼梯确认。
- 返回原楼层时，未击败的怪物仍在，已拿奖励不刷新，开门状态与商店交易记录保留。
- 未购买时可以反复返回商店；每位商人一局只售出一件，购买后不补货；可以穿过商人格继续探索。
- 三种二层主题均提供破晓长枪（攻击 +10）、骑士板甲（防御 +4）、泉水，支持变强后回打一层骑士。
- 初始 100 HP / 10 攻 / 5 防，一层骑士初始致死；仅取得上述两件装备后，满血对战预计损失 77 HP。西侧锁门护甲可进一步降低损失。
- 取得一层骑士身后的王权指环宝箱即达成地图原型目标，之后仍可自由探索。
- 默认菜单、地图中的占位人物 / 格子 / 怪物 / 门 / 道具均由代码绘制。整层可见，没有战争迷雾。

**当前是两层手工布局 + 按种子抽取部分主题怪物 / 奖励。墙体、格子和所有物件的位置尚未随机化，也尚未连接完整十层流程、Boss 与灵魂成长。** 先验证往返体验，再扩展受控随机地图；这不是已经完成的随机迷宫版本。

地图独立存档：`user://tower_map_save.json`，备份为 `.bak`。楼层集合、人物坐标、共享属性、待确认交互和 RNG 状态一起保存，每次移动和资源结算后提交。旧模式的 `user://tower_save.json` 不会被转换或覆盖。

静态检查与地图引擎测试命令：

```powershell
python tools/check_project.py
python tools/check_maps.py
# 安装 Godot 后再执行（目前尚未执行引擎验收）：
godot --headless --path . --editor --import
godot --headless --path . --script tests/map_test_runner.gd
```

新增关键文件：`scripts/core/map_engine.gd`（移动 / 楼层 / 结算）、`scripts/core/map_save.gd`（地图存档验证）、`scripts/ui/map_screen.gd`（地图界面）、`scripts/ui/grid_board.gd`（绘制与格子点击）、`data/map_layouts.json`（两层地图与主题内容）。`tools/build_map_design.py` 是布局与设计图的生成源，执行时需要 Pillow，游戏运行不依赖 Python。

**验证状态：内容、资源引用、中文字体覆盖及 GDScript 静态语法已检查；尚未使用 Godot 导入、编译、运行、截图验收或导出。不能保证首次打开没有引擎级问题，也尚未证明平衡性与 20～40 分钟局时目标。** 详见 `docs/VALIDATION.md`。

## 之后如何运行

1. 使用 Godot **4.3 或更高的 4.x 标准版**作为目标环境，不需要 .NET。首次实际兼容性仍待引擎验证。
2. 在项目管理器中导入本目录的 `project.godot`。
3. 等待中文字体、SVG 图标导入完毕，按 **F6** 运行主场景或 **F5** 运行项目。
4. 点击“开始两层地图试炼”。种子可留空随机，也可以填 `42` 或任意文字；旧模式在菜单内另行进入。

不需要联网服务、账号、插件、外部数据库或额外美术包。开发文件本身不要求安装 Godot。日后运行和导出才需要引擎。

## 已实现的玩法

- 初始 100/100 HP、10 攻、5 防、0 金币、0 钥匙，叠加已购买的局外升级。
- 10 层流程；非首领层有 3 张候选房间卡，只能进入 1 间。第 5、10 层各有 1 个固定 Boss 房间。
- 普通战斗、精英战斗、宝箱、商店、双选项事件和休息点。
- 入场前可见敌人属性、净生命损失、商品价格、事件选项和明确奖励。致死战斗需额外确认，仍允许挑战。
- 玩家先手、最后一击不反击；预览和结算共同调用 `TowerCombat.simulate()`。
- 两个 Boss 使用逐回合机制计算；每次战斗保存可查看的逐击日志。
- 12 件装备、10 件遗物、10 个事件、10 件商店商品，全在 JSON 中配置。
- 装备属性、击杀回血、持有金币转攻击、额外击杀金币；购买后即时重新计算金币相关属性。
- 商店最多购买一件；奖励二选一；钥匙扣除、事件成本、治疗上限在核心层统一处理。
- 固定种子与完整 RNG 状态；选择后自动保存，支持在商店、事件或待领取奖励中继续。
- 死亡 / 通关灵魂结算；3 种永久升级各上限 3 级。
- 最近 30 局的本机旅程记录，包含种子、结果、用时与路线，未接入网络统计。
- 中文字体、响应式纵向滚动界面、窗口宽度上限、鼠标和触控共享点击流程。

## 原型中的具体裁定

设计文档未明确的细节采用以下实现，便于后续调整：

| 项目 | 当前规则 |
| --- | --- |
| 首领数值 | 保留草案：牛头守卫 120/18/8；深渊魔像 250/22/14 |
| 牛头狂怒 | 每第 3 次玩家攻击后，若首领仍活着，攻击 +2，立即影响该回合反击 |
| 魔像石甲 | 每次受击后按累计掉血重新计算；每 50 HP 防御 +2，可一次跨越多个阈值 |
| 首领奖励 | 5 层胜利：65 金币、恢复 45 HP，破晓长枪 / 黑曜战甲二选一；10 层：120 金币并通关 |
| 房间池 | 每层一个战斗位、一个补给位、一个事件位，顺序随机；3、8 层补给位固定商店；4、9 层战斗位固定精英 |
| 锁箱 | 从 3 层后的小概率宝箱抽取，消耗 1 钥匙，装备外额外给 20 金币；无钥匙禁用 |
| 休息点 | 恢复 40 HP，或攻击 +3、防御 +1，二选一 |
| 装备 | 无槽位限制，自动生效，相同物品的每个副本均叠加 |
| 最大生命 | 获得增加最大生命的装备 / 遗物时，同时恢复相同数量的 HP |
| 金币构筑 | 战斗开始时按当前金币计算攻击；本场胜利所得金币只影响下一场战斗 |
| 祭献 | 生命成本必须保留至少 1 HP；不足时禁用对应事件选项 |
| 升级 | 每级分别花费 8、16、24 灵魂；生命每级 +5、攻击每级 +1、初始金币每级 +5，仅新局生效 |
| 灵魂 | 死亡：`max(1, (当前层 - 1) × 2 + 击杀数)`；通关在同公式上额外 +20；主动放弃为 0 |
| 重开 | 进行中的旅程重开需确认，先按放弃结算，再开新局 |
| 复现 | 相同引擎版本、内容、初始升级、种子和选择路径，才具有相同后续结果 |
| 时间统计 | 累计程序运行期间的本局时间（含菜单停留），关闭期间不计入；暂非精确活跃游玩时长 |

所有事件结果都明确展示，本版没有隐藏随机事件奖励、随机暴击或荆棘。没有格子移动、即时战斗、商业美术和音效。

## 项目结构

```text
project.godot                  项目入口、窗口、渲染配置
export_presets.cfg             Web / Windows 导出预设
scenes/main.tscn               主场景
scripts/core/content_db.gd     内容加载、装备与遗物派生属性
scripts/core/combat.gd         无副作用的逐回合战斗函数
scripts/core/run_engine.gd     房间生成、资源结算、本局状态、局外升级
scripts/core/save_store.gd     存档格式、备份、恢复
scripts/ui/main.gd             中文界面（Control/Container 运行时构建）
scripts/ui/tower_art.gd        代码绘制的塔形占位插画
data/content.json             敌人、物品、事件、商品、层数抽池
assets/icon.svg               原创占位图标
assets/fonts/NotoSansSC.ttf   随项目附带的中文字体
assets/fonts/OFL.txt          字体授权全文
tests/test_runner.gd          调用真实核心逻辑的 Godot 测试
tools/check_project.py        无引擎的静态资源与数据检查
docs/VALIDATION.md            已执行检查与未执行验收
docs/DESIGN_SOURCE.md         用户提供的原始设计文档副本
```

界面只发出选择命令与读取状态；资源变化、物品效果和流程推进均在核心层完成。主场景中的具体界面节点由 `main.gd` 构建；调整卡片样式可修改该文件的主题和组件函数。

## 检查与测试

不安装 Godot 时可检查内容和资源：

```powershell
python tools/check_project.py
```

脚本使用标准库；如果环境中存在 `fontTools`，额外检查中文字符覆盖；存在 `gdtoolkit` 则额外检查 GDScript 语法。缺少可选工具时会明确输出 `SKIP`，不是完整检查通过。

有 Godot 后，在项目目录执行（将 `godot` 换为实际可执行文件路径）：

```powershell
godot --headless --path . --editor --import
godot --headless --path . --script tests/test_runner.gd
```

测试使用带进程编号的独立测试存档，完成后删除测试文件，不覆盖玩家存档。包含设计文档的 10 HP 例子、零伤害、致死、先手秒杀、击杀治疗、首领机制、资源扣除、种子复现、备份恢复、通关及一条不购买局外升级的人工合法路线。人工路线不是随机种子通关率的证明。

## 存档

引擎的 `user://tower_save.json` 保存本局和局外成长；`.bak` 为上一份备份。两个部分一起写入同一个文件，避免正常续玩重复发放灵魂。写入先落临时文件，再轮换备份。读取主存档失败时尝试备份并在界面提示。固定种子与 RNG 状态存为字符串，避免 JSON 浮点精度破坏 64 位值。

存储路径可在 Godot 的 **项目 → 打开用户数据文件夹** 中查看。浏览器版使用本地站点存储，关闭隐私会话或清理站点数据可能丢失存档；本项目无云同步。正常每次选择会自动保存；仍需实测各浏览器的持久化行为。

## 导出（配置已备好，未执行）

使用与 Godot 版本匹配的官方导出模板。创建 `build/web` 或 `build/windows` 目录，再通过编辑器的 **项目 → 导出** 使用预设。`data/*.json` 已显式包含，避免导出时遗漏内容表。

```powershell
godot --headless --path . --export-release "Web" build/web/index.html
godot --headless --path . --export-release "Windows Desktop" build/windows/TowerRealm.exe
```

Web 预设采用兼容渲染器、关闭线程；导出结果需要通过 HTTP(S) 服务访问。手机目标当前是竖屏移动浏览器，尚未配置或验证 Android APK / iOS 原生打包。正式分发时也请随包附带字体许可证。
