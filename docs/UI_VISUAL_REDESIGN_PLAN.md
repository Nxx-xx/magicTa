# 塔境 · 界面视觉改造 V01

日期：2026-09-29。状态：本批实施与桌面验证完成；仓库通用静态检查的跨线程目录误报单独记录。

本计划承接 `UI_POLISH_PLAN.md` 的 M1 / M2，不重排整体里程碑。美术方向以用户批准的 `tower_character_map_v01.png`、`hero_design_v01.png` 为准：精绘轻 2.5D、深蓝灰、克制古金、青绿和少量暖色；覆盖总计划早期未定稿的像素风提案。

## 现状与限制

- `map_screen.gd` 原生动态构建界面，M1 已固定 HUD、11×11 地图和方向控制；详情、行囊、商店、奖励与结果使用独立滚动面板。宽窗口目前居中，不新增侧栏。
- `map_theme.tres` 已提供基础按钮与生命条，但面板样式散落在脚本，信息层次偏平，选择项未独立成卡；原生确认窗口尚未统一主题。
- 真实像素响应式布局必须保留。320×640 是极窄回归，360×640 是最小主要验收窗口；窄屏地图格不满足大触控尺寸，因此方向按钮始终保留。
- 保存异常是弹层之后的独立面板；后台按钮禁用且退出 Tab 遍历；退出场景恢复 Window 缩放设置。这些是不可回退的已验收行为。
- 地图、角色与怪物仍用当前程序占位验证。其他线程的素材和预览只读，最终接入不属于本批。

## 实施顺序

1. **计划与基线**：保存本计划、备份现有界面文件；检查当前真实渲染与测试入口。
2. **主题与探索**：集中面板/按钮样式，建立主要/次要/危险操作层级；完善 HUD 背板、地图外细框与方向控制，不改变布局计算的核心约束。
3. **状态覆盖**：奖励、商店、事件、休息和楼层选择分卡；行囊清晰分组；确认窗口统一；菜单与结果复用主题。
4. **验证与修订**：隔离导入、现有 UI / M1 回归、专属真实截图检查，发现裁切或焦点问题即修复；保留有意义断言。
5. **交付**：更新本计划、记录实际测试数量与截图，明确后续工作。

依赖仅为现有引擎、字体、核心 API 和占位绘制；不等待其他美术线程。

## 验收标准

- 在 320×640、360×640、540×960、900×960 查看探索、敌人损失、确认、行囊、奖励、商店、菜单及结果等关键状态；地图/控件无重叠裁切，窄屏长中文不横向溢出。
- 固定 HUD 和方向控制保留，触控目标至少 44px；三钥匙有文字区分。禁用原因可读、焦点轮廓可见、主要操作明确。
- 弹层背后不能移动或 Tab 聚焦；确认/取消返回可操作状态。保存异常在详情、待选、行囊和结果状态持续可见。
- 返回营地、继续探索、退出恢复缩放、已有战斗/奖励/商店测试通过；不以删断言掩盖失败。
- 截图来自 Godot 真实渲染，置于独有 build 目录；APPDATA 和 LOCALAPPDATA 全部隔离，不访问玩家存档。
