# 第二阶段交付：十层旅程与公主救援

日期：2026-09-30。Godot 4.7.2，Windows x86_64。本次由统筹集成、地图玩法、剧情成长、界面表现四个协作任务完成，共享工作区按模块分工，最后统一回归。未提交 Git，也未覆盖工作区原有的第一阶段改动。

**可玩版本已落地；完整发行验收尚未结束。** S2-A～S2-E 的运行时功能已接入。S2-F 的自动化、实际生产路线通关和 Windows 便携包验证已完成，外部玩家与移动平台验收留在待办中。

## 试玩交付

- [Windows 压缩包](../build/phase2/TowerRealm-Phase2-Windows.zip)：解压整个目录，双击 TowerRealm.exe。
- [本机已展开目录](../build/phase2/windows/)：TowerRealm.exe 和 TowerRealm.pck 必须位于同一目录。
- 进入“营救王子 · 十层旅程”，种子可留空，也可输入 42。两层地图试炼仍有独立入口。
- 源码入口：`scenes/map_prototype.tscn`。操作、存档位置与开发命令见 [README](../README.md)。

本机缺少匹配版本的官方 Windows / Web 导出模板，标准 Windows release 导出明确失败。交付使用本机 Godot 可执行文件搭配导出的独立 PCK，已在包目录启动并验证资源和续存；属于便携测试版本，运行时体积较大。不能据此声称正式模板发布、Web 或原生手机打包已完成。包内附带 Godot、第三方组件及字体授权说明。

## 实现范围

| 方面 | 当前实现 |
| --- | --- |
| 地图 | 十层、六种普通层几何布局、两种独立 Boss 关隘；旋转镜像、首次主题锁定、跨层往返与状态保留 |
| 成长节奏 | 早期保底武器 / 护甲、第五层选择奖励、第六层另一成长方向；两商店、两休息点、三事件 |
| 投放预算 | 全塔最多 14 个装备 / 17 个遗物机会，二选一候选、商品展示和事件奖励一并计入，不等同于实际获得数量 |
| 首领 | 第五层牛头守卫封锁进度，第十层魔王附身深渊魔像；十层快照攻击为 28，旧试炼内容表不随之改变 |
| 主线 | 序章、关键层对话、中段首领、可选指环、失败回声咒、王子协作与营救结局；跳过和读档不重复触发奖励 |
| 局外 | 灵魂结算、三种火种各三级、免费退款重置；唯一旅程 ID 防重复结算，保留近 30 局记录 |
| 复盘 | 成功 / 失败 / 放弃，路线和资源统计、只读地图、同种子重试、新种子再战 |
| 界面 | 楼层索引、目标标记及损失更新、小屏滚动、模态输入隔离、保存失败阻断及重试 |
| 表现 | 环境 / 四向公主 / 六普通怪 / 四精英首领静态图；王子与魔王对白图、营救结局图；基础声音、王子短呼声、音量和减动效设置 |

故事使用非性化的魔法“回声咒”和远处呼声。王子声音是 Windows 系统语音加工的原型，未使用真人录音或声音克隆。死亡演出仅在保存成功后首播；读取已结束旅程展示静态摘要。

旧 `map_engine.gd` 的两层玩法保留。新 `campaign_engine.gd` 在其基础上增加正式旅程；两种模式使用同一个 `run/meta` 存档封装。一个账户只有一个当前旅程，重开须确认放弃，不是独立的双存档槽。奖励、怪物、地图计划与规则快照随局保存，后续内容表变化不会中途更改本局。

## 集成中修复的问题

- 结算与账户一起原子提交；写入失败回滚至已提交状态，保留同一候选事务重试，禁止继续消耗资源或新开局。
- 损坏主存档恢复后继续保存时保护原有有效备份；损坏原文保留为诊断副本。
- 防止坏类型、越界坐标、站在未处理敌人 / 门格、无效待确认引用和损坏战报进入界面；保留历史存档兼容。
- 修正以实时内容表计算已冻结旅程预算、新试炼保存失败仍返回成功、回溯后最高楼层记录降低等问题。
- 保存失败时，退出按钮和关闭窗口均说明将丢弃未保存变化，默认取消；取消后可继续重试保存。
- 修正小屏标题遮挡、怪物身份、主题中文名、回溯角标和动态贴图路径检查。
