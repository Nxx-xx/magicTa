# 塔境 · 两层 Demo 界面美化开发计划

日期：2026-09-29  
状态：M0 基线、M1 主界面样板及首批美术候选已完成；M1 修订版已合入原目录，后续阶段待推进  
阶段目标：将现有两层可玩 Demo 打磨成风格统一、信息清晰、操作顺手的展示版本。

## 1. 当前基础与本轮目标

当前默认入口为 `scenes/map_prototype.tscn`：两层 11×11 随机方格地图，支持跨层回溯、战斗预览、三色钥匙、装备与遗物、奖励二选一、事件、休息点、商店和自动存档。旧版十层卡片模式已移除，历史地图存档兼容保留。

本次会话已使用本机 `godot` 中的 Godot **4.7.2** 导入项目，并复跑七组无窗口测试：**4,904 项、零失败**。这是现有逻辑和界面脚本的验证基线，不代表新界面、真实触控或导出已通过验收。既有历史记录见 [VALIDATION.md](VALIDATION.md)。

本轮完成后，玩家应能：

- 进入游戏后迅速找到开始、继续和操作说明。
- 在主界面持续看到生命、攻防、金币、钥匙及当前楼层。
- 看清完整地图，并在附近完成目标查看与操作，无需反复寻找页面下方按钮。
- 在确认前理解战斗代价、开门成本、治疗效果和购买后的实际属性。
- 从移动、开门、战斗、拾取的反馈中明确知道操作已经生效。

优先验收 Windows 桌面窗口，兼顾窄屏布局。Web 和手机实机验收作为后续独立任务，不能用桌面缩窄窗口替代。

| P0 | 交互状态与信息 | 明确查看、待确认、不可操作、已完成四类状态，保留准确的预览与取消入口 |
| P0 | 基础视觉规范 | 统一配色、字体层级、间距、按钮和面板，先做主界面样板 |
| P1 | 地图美术 | 替换人物、地形、当前投放怪物和交互物件的占位表现 |
| P1 | 辅助页面 | 统一菜单、行囊、商店、奖励、事件、休息点、楼层选择和探索结果 |
| P1 | 动画与音效 | 加入短促、可辨认的操作反馈，提供音量与减少动效选项 |
| P0 | 回归与交付 | 逻辑回归、真实渲染截图、鼠标键盘试玩及 Windows 导出试玩通过 |

存档字段校验不足是前次审查发现的独立问题。应在正式对外发布前处理，并增加损坏字段的恢复用例；它不阻塞主界面样板制作，也不计入本轮美术工期。

## 3. 视觉方向与首个样板

暂以 **暗色石砖地牢、暖金色界面、清晰像素角色与物件** 为工作方向。这是样板提案，尚未作为最终美术定稿；先验证主界面实际效果，再批量制作素材。

### 基础规范

| 项目 | 初步规格 |
| --- | --- |
| 背景与层次 | 深蓝黑背景，石灰色墙体，通路比墙体更暗；用明暗和轮廓区分可行走区域 |
| 强调色 | 暖金用于重要操作与奖励，青绿用于角色与恢复，柔和红用于损伤和致死提示 |
| 类型识别 | 铜、银、金钥匙同时使用颜色、轮廓或文字标记；不能仅靠颜色区别 |
| 字体 | 继续使用随项目附带的 Noto Sans SC，保证中文清晰；像素风不强制使用难读的像素字体 |
| 字号 | 以 540×960 逻辑视口为基准：标题 24～28、关键数值 18～22、正文 16～18、辅助信息 13～14；最终按实际缩放检查 |
| 间距 | 采用 4 / 8 / 12 / 16 / 24 的间距档位，统一边距与对齐 |
| 按钮 | 默认、悬停、按下、禁用、键盘焦点均有可见差异；主要操作触控目标以 44～48 个逻辑像素为起点 |
| 地图素材 | 首轮以 32×32 像素格为候选规格，使用统一视角和光源；在实际格子尺寸验证后定稿 |
| 图标表现 | 地图上的小图标突出轮廓；详细属性与长文放入详情区，避免把文字堆进格子 |

非整数缩放可能让像素边缘不均匀，阶段一必须对比实际 11×11 地图效果，再决定整数缩放留边或调整素材规格。三种二层主题先用少量装饰与色调区别，不各自制作完整地形套装。

### 主界面布局

```text
┌──────────────────────────────┐
│ 塔境 · 当前楼层       菜单入口 │
│ 生命条 / HP      攻击 / 防御   │
│ 金币       铜 / 银 / 金钥匙    │
├──────────────────────────────┤
│                              │
│          11×11 地图          │
│                              │
├──────────────────────────────┤
│ 目标名称 · 状态 · 核心预览     │
│ 主要操作               返回   │
├──────────────────────────────┤
│ 方向控制       行囊 / 战斗记录 │
└──────────────────────────────┘
```

- **540×960 标准窗口**：常规探索时状态栏、完整地图和方向控制同时可见；详情区限制高度，长文独立滚动。
- **360×640 最小窗口**：保留完整地图和关键状态，详情改为可展开面板；展开时允许遮挡部分地图，但地图操作暂停，关闭后恢复。
- **900×960 宽窗口**：地图保持方形，允许将详情和行囊入口移至侧栏；避免把格子无限放大。
- **320 像素宽测试场景**：保留已有极窄宽度回归，用于发现溢出；不等于承诺低于项目最小窗口的完整体验。
- 地图小格在窄屏下无法保证每格都是大触控目标，因此必须保留独立方向按钮，不以格子点击作为唯一操作方式。

第一份样板交付：实际 Godot 主界面，包含普通探索、选中怪物、致死提示三种状态，以及标准窗口和最小窗口截图。

## 4. 交互设计要求

| 场景 | 界面行为与必须保留的信息 |
| --- | --- |
| 查看与移动 | 点击远处格子只查看；相邻格或方向控制按既有规则移动。查看状态不出现可以远程执行的挑战或拾取按钮 |
| 普通战斗 | 显示敌人身份与档次、攻防血、预计净损失、实际受伤、击杀回血；击杀奖励与身后守护奖励分开 |
| 致死战斗 | 使用明确文字提示“当前挑战会死亡”，继续挑战仍需额外确认；不能仅凭净损失或颜色推断安全性 |
| 门与钥匙 | 显示门类型、对应钥匙库存和消耗；数量不足时说明原因；开门后通路状态立即更新 |
| 药剂 | 显示实际恢复及溢出量，确认后消耗；满血经过仍保留 |
| 商店 | 显示价格、购买后余额和最终属性，包含金币遗物带来的攻击变化；购买一次后明确标记售罄 |
| 选择奖励 | 两项并列或纵向对齐，清楚展示不同收益；一旦领取只结算一次，取消和读档不刷新候选 |
| 事件与休息 | 显示成本、收益与不可选原因；生命成本保留至少 1 HP；关闭面板按既有取消规则执行 |
| 行囊与战斗记录 | 同名物品合并数量、保持效果叠加；长列表独立滚动，不挤走地图；日志保留逐击明细 |
| 楼梯与主题 | 首次上二层选主题，回访只确认移动；明确楼层状态保留 |
| 完成与死亡 | 获得目标指环后提示完成并保留继续探索；死亡后提供重新开始和返回菜单 |

布局变化不得省略损失与成本预览。重复点击、按住方向键、弹窗打开时按键，以及取消后再次交互，都要有明确且一致的处理。

## 5. 分阶段任务与交付

工期为单人连续投入的粗估，假定复用现有核心逻辑、没有付费素材采购等待，暂计 **10～16 个工作日**。并非交付日期承诺；阶段一完成后，根据素材产能和实际界面改动量重新估算。

| 阶段 | 任务与交付物 | 验收条件 | 粗估 |
| --- | --- | --- | --- |
| M0 基线整理 | 保存固定种子及受控交互场景截图；列出当前界面问题；记录引擎、窗口、测试日志位置 | 有可重复的改造前样本；存档和测试目录隔离 | 1 日 |
| M1 主界面样板 | 提取主题资源；实现状态栏、地图、目标面板和控制区；提供标准 / 最小窗口样板 | 探索不依赖整页滚动；三种样板状态可操作；确定视觉与素材规格 | 2～3 日 |
| M2 交互与页面 | 完成战斗、门、药剂、商店、奖励、事件、休息、楼梯、行囊、菜单及结果界面 | 所有状态入口、确认、取消、禁用原因完整；预览与原核心结算一致 | 2～3 日 |
| M3 美术接入 | 制作并接入首批地形、角色、怪物和道具；建立资源映射与来源清单 | 当前实际投放内容都有清晰图像；小尺寸可辨认；缺失资源有占位回退 | 2～4 日 |
| M4 动效与声音 | 增加移动、开门、拾取、战斗和完成反馈；提供音量 / 减少动效设置 | 连续输入不重入结算；音效无叠加爆音；减少动效后仍能理解结果 | 1～2 日 |
| M5 验收与交付 | 七组回归、实际渲染、三主题回溯试玩、Windows 导出及独立启动；整理问题和截图 | 本文验收清单满足；阻断操作和数值错误全部解决；交付可运行包 | 2～3 日 |

依赖顺序：M0 → M1 → M2 → M3 → M4 → M5。M1 的布局与视觉样板完成后再批量制作美术；M3 期间可分批替换素材并随批验证。工期紧张时缩减装饰、主题变体和非必要待机动画，保留 P0 信息与操作要求。

### 首批美术与声音清单

- 地形：基础地板、墙体及必要边角、上下楼梯、营地和终点标识；先保证边界和通路清晰。
- 角色：一套玩家四向静态形象，基础移动反馈；多帧待机与复杂攻击动作后续扩展。
- 怪物：覆盖当前两层配置实际使用的普通怪 ID，最多六种；保留档次与回溯守卫标记。两精英、两 Boss 暂用现有表现。
- 物件：三种门、三种钥匙、金币、药剂、普通箱、选择箱、目标箱、商人、事件、休息点。
- 物品图标：覆盖当前两层可获得装备与遗物；其余物品继续使用已有 `item_icon.gd` 回退表现，避免缺图。
- 通用界面：面板、按钮、生命条、焦点与选中框、提示图标、菜单标题区。
- 声音：确认、取消、移动、开门、拾取、受击、胜利等约 6～8 个短音效；背景音乐为可选项。
- 每项记录文件路径、对应 ID、规格、制作或下载来源、授权说明与接入状态。沿用中文字体时继续保留 OFL 许可证。

## 6. 实现安排

### 现有代码的改造位置

| 文件 | 计划调整 |
| --- | --- |
| `scripts/ui/map_screen.gd` | 从每次操作重建整页，逐步改为稳定容器与局部状态刷新；负责页面和面板状态协调 |
| `scripts/ui/grid_board.gd` | 保留格子坐标、点击和地图数据接口，接入材质图像、选择反馈和移动表现 |
| `scripts/ui/monster_art.gd` | 保留无图时的占位绘制，增加统一怪物素材入口或映射 |
| `scripts/ui/item_icon.gd` | 接入物品图标，保留现有回退；按物品 ID 映射，避免依赖中文名称 |
| `scenes/map_prototype.tscn` | 根据布局需要承载稳定节点，便于 Godot 编辑器预览与调整 |
| `tests/monster_ui_test_runner.gd`、`tests/reward_ui_test_runner.gd` | 保留行为断言，适配新节点结构，增加遮挡、焦点和重复输入相关验证 |
| `docs/VALIDATION.md` | 在完成对应验收后追加新阶段记录，明确无窗口、真实渲染和导出的区别 |

建议新增 `assets/ui/`、`assets/tiles/`、`assets/characters/`、`assets/monsters/`、`assets/items/`、`assets/audio/` 目录；主题资源和组件按实际需要拆分，避免一次重构整个项目。

### 状态与动画约束

1. 玩家生命、金币、奖励、地图实体和楼层状态仍由 `MapEngine` 修改；UI 读取结果并调用已有命令。
2. 战斗与奖励预览继续使用 `TowerCombat`、`RewardRules`，不另写一套界面公式。
3. 移动和结算先由核心确认，再播放表现。存档不等待动画完成，关闭窗口不会丢失已提交的奖励。
4. 动画回调不能重复发奖或扣资源；快速连续操作、取消、场景切换时正确结束动画和清理回调。
5. 明确区分选中目标与待确认目标，刷新局部节点时同步更新按钮可用状态和数值。
6. 弹出交互面板时拦截地图输入，关闭后恢复；方向键、WASD 与按钮共享核心移动入口。
7. 减少动效模式使用即时位置和简短状态提示；音量偏好单独保存，不混入本局进度存档。

## 8. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 长详情挤占地图 | 将详情、行囊和记录分区；标准窗口限制详情高度，最小窗口使用可展开面板 |
| 像素素材缩放模糊或细节过多 | 在真实格子大小先验样板；统一导入过滤和像素规格，轮廓优先 |
| 装饰遮挡路线、门或奖励 | 墙地对比和交互物优先；装饰不承担判定，不遮挡关键图标 |
| 动画导致重复操作或存档不同步 | 核心先提交、表现后播放；针对快速输入、取消、关闭窗口做回归 |
| 素材工作量超出预估 | 只覆盖当前两层实际内容，复用地形与通用面板，高阶怪物和主题变体后移 |
| 改界面时无意改变玩法 | 每个阶段保留核心回归；数值调整单独立项，截图受控场景不冒充自然生成结果 |
| 版本和导出环境差异 | 以本机 Godot 4.7.2 为本轮基线，记录模板与渲染设置；升级后重新验证 |

## 9. 第一批执行清单

后续开始实施时，先完成 M0 与 M1：
