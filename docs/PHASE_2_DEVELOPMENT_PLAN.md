# 第二阶段开发计划：十层魔塔与王子救援

计划日期：2026-09-29。实施更新：2026-09-30，十层可玩版本已接入。本文保留原开发目标；已实现范围、测试证据及尚未完成的外部试玩 / 平台验收，以 [第二阶段交付记录](PHASE_2_DELIVERY.md) 为准。

依据用户本轮确认，第一阶段已完成，第二阶段增加地图层数，并加入公主拯救王子的主线、失败剧情和合理的玩法完善。本计划承接当前代码，第一阶段完成不等于历史文档中的每个未来功能或平台验证均已完成。

剧情正文和台词见 [第二阶段剧情设计](STORY_DESIGN_PHASE_2.md)。奖励与成长分别承接 [奖励设计](REWARD_DESIGN.md)、[灵魂与火种](META_PROGRESSION.md)，发生冲突时本计划负责明确第二阶段的实施范围，不把旧文档中“已实现”直接当作当前事实。

## 1. 阶段交付目标

交付一局能从营地出发、探索十层、打败魔王并救出王子的可运行 Demo。玩家能够理解失败为何重开、为什么需要回溯，以及不同奖励怎样影响下一次行动。

- 两层试炼保留为独立入口和旧存档兼容模式；新增“营救王子 · 十层旅程”。
- 十层保留 11×11、四向移动、确定性战斗预览、三色钥匙、跨层回溯和首次生成后固定的规则。
- 第 5 层为牛头守卫，第 10 层为魔王终战。复用现有 `golem` 战斗机制，剧情中设定为魔王附身的深渊魔像；显示名称和素材要让玩家明确正在挑战魔王。
- 公主战败后被提灯送回营地；魔王对王子施加一次非性化的回声咒，远处传来短促惨叫。死亡计数跨本档重开保留，敌人难度不随失败上涨。
- 完整支持失败结算、同种子重试、新种子再战、首次通关结局及已结束旅程记录。
- 接入有限灵魂成长，但必须先证明零升级路线能通关。

“约 20～40 分钟一局”沿用原设计作为待测目标。不得用增加空走、重复弹窗或无意义战斗硬凑时长。

## 2. 十层内容与节奏

楼层编号决定固定职责，主题只改变可选支路。第 1 层入口、第 5 / 10 层 Boss 固定；第 2、3、4、6、7、8、9 层首次进入时选择战斗、宝藏、商店主题，之后锁定。不能通过主题跳过固定补给或挤掉必要成长。

| 层数 | 场景名（暂定） | 核心体验和投放 | 剧情节点 |
| --- | --- | --- | --- |
| 1 | 旧王庭入口 | 弱怪教学、早期装备；骑士与王权指环保留作可选回溯支路 | 公主入塔，明确王子在塔顶 |
| 2 | 回声回廊 | 攻防基础成长；第一次主题选择和路线比较 | 王子通过传声石提供线索 |
| 3 | 灰烬集市 | 保证一名商人；可选金币与装备路线 | 商人说明塔内交易规则 |
| 4 | 封印前庭 | 保证休息点；3～4 层合计一次血斧狂徒可选挑战 | 得知魔王靠王室封印维持塔顶结界 |
| 5 | 牛头关隘 | 必经 Boss；胜利一次性金币、治疗与装备二选一 | 打破外环封印，首次正面对话 |
| 6 | 断誓兵库 | 可回退成长支路放置中段 Boss 未选的另一件装备 | 王子透露自己正在破坏结界内部 |
| 7 | 镜影回廊 | 强化攻击、防御、财富方向；安排一次完整回溯决策 | 公主与王子短暂直接通讯 |
| 8 | 黑铁监区 | 保证第二位商人；8～9 层合计一次典狱长可选挑战 | 找到塔顶入口信息，王子给出最后线索 |
| 9 | 黎明前室 | 保证休息点；终战预览与准备，可返回下层 | 两人约定打破封印的时机 |
| 10 | 魔王观星台 | 魔王附身的深渊魔像；击败后营救、结局、最终结算 | 公主    打破外壳，王子破坏内部封印，两人离塔 |

普通层继续以安全主路和最多四条支路为基线。商人可占安全位置，但全塔最多三位；事件、休息点和精英占用支路名额。第 5 / 10 层使用独立 Boss 模板与校验规则，避免普通层“安全直达出口”约束使 Boss 可绕过。

第 5 层 Boss 未击败前不能进入第 6 层，但可以返回第 4 层；击败后必须领取阶段二选一才能上楼。第 10 层挑战前可回退，击败后进入营救结局。Boss 均不刷新。

## 3. 地图和回溯整改

### 3.1 生成结构

- 保留两层生成器版本 0～3 的语义，新十层使用独立战役规则和生成版本，不直接把所有 `[1, 2]` 替换为十层。
- 新增全塔计划：固定成长、奖励份额、商店位置、休息点和精英名额在开局预留；楼层几何在首次进入时展开。
- 首批目标为六套普通层拓扑和两套 Boss 专用拓扑；优先复用并扩展现有三套模板。旋转、镜像不计作新拓扑，相邻普通层尽量不重复模板。
- 普通层分成 1～4 层石质王庭、6～9 层黑铁监区两组环境表现；Boss 层通过布局与重点物件区分，不要求十套独立美术。
- 每层记录独立生成种子、主题、模板、实体 ID 和生成版本；故事对白及音效使用独立序列，不消耗地图 RNG。
- 普通层必须检查安全往返、守卫切断关系、同色钥匙和成长依赖；Boss 层必须检查唯一进度门槛、安全撤退和奖励领取状态。

### 3.2 回溯操作

- 增加楼层索引，显示已到达楼层、未清守卫、待领奖励、商人售罄和一次性设施使用状态。
- 允许标记已发现目标；获取装备后可比较标记敌人的损失变化。
- 第一版楼层索引只导航信息，不引入跨层传送。先记录真实回溯耗时，再决定是否加入“已打通安全路径的快速往返”。
- 窄屏保留方向按钮，楼层索引与剧情界面不得挤掉生命、关键损失和关闭入口。

## 4. 成长、奖励和经济

十层使用正式成长曲线，不复制两层试炼第二层直接给长枪与板甲的强度。

| 阶段 | 基础供给 | 需要验证的选择 |
| --- | --- | --- |
| 1～2 层 | 铁剑、铁甲；一至两份可选装备；一次初阶遗物机会 | 先拿攻击、先拿防御或保留补给 |
| 3～4 层 | 淬钢刃、板甲；商人、休息点；一次可选精英 | 花钱减损、保留财富遗物攻击、挑战精英 |
| 5 层 | 牛头奖励和长枪 / 黑甲二选一 | 用中段选择确立成长方向 |
| 6～7 层 | 未选的另一件中段装备；进阶遗物、生命扩容机会 | 回溯骑士、强化当前方向或补齐短板 |
| 8～9 层 | 商人、休息点、一次可选精英及少量补给 | 终战生命预算与可选收益取舍 |
| 10 层 | 营救和结算奖励 | 不用最终掉落反推通关所需属性 |

- 沿用 12 装备、10 遗物、10 事件与现有敌人作为首批内容库，先调整投放和时机。
- 三类构筑目标为高攻击减少回合、防御配合击杀恢复降低连续消耗、金币转攻击形成消费取舍。不宣称它们已经平衡。
- 全塔装备份额同时计算宝箱、二选一候选、商店陈列和事件机会，防止主题选择导致必要成长缺失或超发。
- 3～4 个事件、两次固定休息、至少两位至多三位商人为起始配置。商人仍最多购买一件，重新访问不刷新。
- 普通门首版沿用同色钥匙足额保障；必要通路不做钥匙赌博。钥匙稀缺和互斥开门留待路线验证后独立评估。
- 使用真实战斗函数逐步模拟整段当前生命、最低生命、治疗溢出、金币和派生属性。单场满血可赢不等于全塔可通。

### 局外成长

十层正常死亡：普通与精英击杀每只 2 灵魂，Boss 每只 5；通关另加 20；主动放弃为 0。沿用三条各三级的生命、攻击、金币火种及局后免费重置。两层试炼不产出灵魂，也不应用火种。

王子受罚次数是剧情记录，与灵魂账户分开；没有受罚次数换奖励、额外敌人强化或失败次数限定坏结局。营救只依赖完成本局目标。

## 5. 剧情与交互

- 新档序章约 30～45 秒，可跳过；重开用一句承接对白替代完整序章。
- 首次进入关键楼层、首次获得成长装备、击败中段 Boss、取得王权指环、战败和终战胜利触发剧情。
- 重复楼层访问不重复播放主线对白。商店 / 战斗待确认时不插入抢焦点剧情；事件排队，在当前交互结束后展示。
- 王权指环在两层模式仍完成试炼目标；十层模式只完成可选支线并提供既有装备收益，不能把十层旅程标成完成。
- 失败采用远处的非性化魔法受罚声、字幕和简短对白。演出约 2～3 秒，可立即跳过；每次失败结算一次，不靠突然提高响度制造效果。
- 提供语音 / 效果音音量、关闭受罚语音和减少动效；关闭声音仍保留剧情字幕和正常结算。
- 完成面板展示救援结果、种子、路线、关键装备、击杀、生命消耗与灵魂明细；可查看本局地图复盘，复盘为只读，不再触发死亡或收益。

### 存档和失败幂等

1. 区分 `campaign_kind`（`trial_2f` / `tower_10f`）、唯一 `run_id`、剧情规则版本、全塔奖励计划、内容快照与故事节点状态。重复同一种子也必须生成新的 `run_id`。
2. 十层失败记录使用稳定的事件键，例如 `run_id:death`。在状态副本中同时完成本局死亡、一次性灵魂结算、累计失败次数和待呈现剧情的登记，然后整体提交。
3. 保存成功才替换正式内存状态并播放新失败事件；保存失败保留同一候选事务、允许重试，阻止新开局覆盖待提交进度。重复点击和重试不会多算一次。
4. 重载一个已结束局只显示已结算结果，不再次累计或自动播放惨叫。尚未展示的失败事件在重载后转为静态摘要；已看到的对白可主动回顾。
5. 退回营地、退出程序、取消战斗、主动放弃、生成失败、读档失败不算战败。旧两层死亡不补记剧情次数。
6. 开始下一次十层旅程保留本档剧情累计次数与灵魂；本局地图和装备重建。第一版不增加多档位或“清空账号”入口。
7. 冻结敌人、物品、事件、商品及必要规则版本，防止更新后旧局预览变化；校验数值、范围、位置、实体引用、待交互及结算状态一致性。
8. 旧局整体迁移并保留布局与既有规则。已清除实体的存档使用状态一致性检查，不能套用“初始地图必须拥有所有守卫”的生成校验。

## 7. 美术与声音清单

- 复用现有成年女性主角设定作为公主：银白短发、青绿斗篷、右剑左灯，以及已有对话半身立绘。
- 新增王子和魔王对话立绘各一张、营救结尾插图一张；先文字占位联通剧情，再制作最终插图。
- 覆盖实际投放的六普通怪、两精英、两 Boss；现有普通怪素材优先复用，余烬术士随十层配方正式投放。
- 地图使用两组环境色调、Boss 场景重点物件、传声石与封印标记；新增剧情物件不能无意阻塞安全主路。
- 首批声音包含脚步、拾取、开门、命中、回声咒、远处短惨叫三条变体、中段胜利和营救完成。无需首版全对白配音。
- 所有语音记录来源或授权；远近感靠滤波、混响和衰减，不能让惨叫比战斗效果明显更响。长时间或连续输入不叠播同类声音。

## 8. 实施里程碑

顺序 S2-A → S2-B → S2-C → S2-D → S2-E → S2-F。工期是单人净工作日估计，不是交付承诺；不包含外部配音或素材返工等待。

| 阶段 | 工作与可审阅产物 | 完成标准 | 估计 |
| --- | --- | --- | --- |
| S2-A 基础与兼容 | 修复通用静态检查误报；模式、存档迁移和全塔计划结构；统一当前文档 | 老试炼回归通过；损坏字段回退；十层配置可校验 | 2～3 日 |
| S2-B 十层骨架 | 普通层及 Boss 模板、上下楼、主题锁定、阶段奖励、最终出口 | 固定种子走完 1～10 层；Boss 不可绕过；跨层状态和读档一致 | 3～5 日 |
| S2-C 剧情闭环 | 序章、关键楼层对白、失败回声咒、目标追踪、营救结局 | 一次真实死亡只记一次；重开承接；一次胜利完成营救；跳过 / 静音可用 | 2～3 日 |
| S2-D 构筑与局外 | 全塔奖励额度、商人 / 事件 / 休息、三类路线、灵魂与火种 | 零升级参考路线通过；多路线产生不同代价；灵魂结算和重置不重复 | 3～4 日 |
| S2-E 表现与操作 | 角色 / 怪物 / 环境接入、基础声音、楼层索引、复盘页 | 标准 / 窄屏可读，焦点无穿透，地图识别与远处声反馈成立 | 3～5 日 |
| S2-F 验收与交付 | 整塔回归、真实试玩、Windows 包及 Web / 移动浏览器验证 | 发布阻断项关闭；可运行包、日志、截图和已知限制齐备 | 2～4 日 |

合计约 15～24 个净工作日。每个里程碑提交可玩的阶段构建；S2-B 与 S2-C 可用占位美术。若需缩小首发范围，先缩减演出变体和装饰，不削减十层、营救结局与可靠的失败结算。

| 验收面 | 必须得到的证据 |
| --- | --- |
| 兼容 | 旧手工 / v1 / v2 / v3 两层样本可续玩，老入口无变化；两层不发十层奖励 |

| 真实试玩 | 首轮 5～8 人，每人至少两局；记录完成率、卡关楼层、选择理由、局时、回溯时间和是否愿意换路线重开 |
| 导出 | Windows 独立启动与续存；Web 实际 HTTP(S) 启动；至少一台目标手机浏览器触控、后台返回、音频解锁和本地保存 |

几何合法与参考路线可通是两类证据。百种子测试不等于数学上证明所有种子都有解；发布生成规则还须保证阶段保底与最坏资源预算，失败时有确定的合法模板回退，并记录种子供复现。

试玩记录优先保存在本地：种子、模式、主题、击杀、领取、消费、实际损失、溢出治疗、死亡原因、局时和回溯步数。首版无需账号或联网遥测。
