## 执行边界

1. 三个执行聊天各用独立 worktree，起点为分派时的当前工作区，包含用户 Godot 4.7 导入设置和美化计划。原目录保留给用户运行及统筹集成。
2. 用户已在 Godot 中导入项目；保留现有配置和导入元数据，不回退、清理或覆盖原目录中的改动。
3. 各聊天只编辑自己的文件；需要共享文件改动时，在交付报告写清所需接口，由统筹协调归属。
4. 界面聊天先用现有绘制资源完成结构，美术聊天只交付少量样品；首批不并行改 `grid_board.gd`、`monster_art.gd` 或 `item_icon.gd`。
5. 测试聊天第一批只验证原始基线，不能把该结果说成新界面已通过。界面整合后再分派新一轮验收。
6. 不更改战斗、奖励、随机地图数值和存档格式，不运行素材全量生产，不下载或安装额外引擎。
7. 引擎路径为 `godot`。各 worktree 设置独立的 `APPDATA`、`LOCALAPPDATA` 和日志目录，不使用玩家正式存档。
8. Godot 导入会生成 `.godot/`、UID 和导入元数据；区分必要新增资源文件与无关导入噪声。构建、截图和日志留在忽略目录；报告列出准确绝对路径。
9. 每个聊天完成后给出：工作副本路径、改动清单、运行/验证方式、截图或样品路径、未解决问题。未经整合验证，不声称整体美化完成。
10. 统筹通过聊天状态和交付报告协调；执行聊天无需另行发送聊天消息，也不自行创建更多聊天。
