3. 桌面窗口 540×960 / 横屏 / 缩放后，中文、按钮、滚动、弹窗无重叠或裁切。

5. 真正试玩死亡与通关；所有房间卡预览和结算一致，生命 / 金币即时更新。
6. Web 导出后用 HTTP 服务打开，确认 JSON 和中文字体包含在导出包中。
7. 移动浏览器触控、滚动、后台恢复、本地存储持久性验收。
8. 固定 20～50 个种子试玩并记录通关率、失败层、房间选择、构筑与局时。

## 仍需校准的设计问题

- 保留设计稿 Boss 原始数值，未经真实引擎批量模拟或试玩调参。
- 第 5 层加入 45 HP 治疗和强装备二选一，让第二幕有继续成长的补给来源。
- 稀缺层数可能让攻击 / 防御积累优于普通战斗刷金币；需评估商店价格与普通战斗吸引力。
- 防御达到深渊魔像攻击时可零伤通关，这是设计稿允许的规则，是否削弱仍需试玩决定。
- 没有测得 20～40 分钟一局；十层即时结算原型可能明显更短。
- 缺少真实引擎运行和视觉 QA，交付不是已经验证可发布的成品。
