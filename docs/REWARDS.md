# 奖励系统使用说明

2026-09-29，第一阶段已接入当前两层方格地图。完整后续方案见 [奖励设计](REWARD_DESIGN.md)。原十层卡片模式继续保留原奖励、Boss 与灵魂规则，两种模式独立存档。

## 开始体验

在地图菜单开始新试炼，种子可填 `42`。第一层与三种第二层主题仍保留原回溯路线：绕过骑士 → 史莱姆后取长枪 → 银门后取板甲 → 返回骑士身后领取指环。

新开局使用第3版生成器，奖励差异如下：

| 地图位置 | 新行为 |
| --- | --- |
| 一层开放治疗、所有主路药剂 | 受伤时进入使用确认；满血经过不消耗；可以取消并留到以后 |
| 二层战斗主题的遗物守卫后 | 固定的遗物二选一，至少一件直接属性遗物；领取一件并获得原附赠金币 |
| 二层宝藏主题的金门后 | 长弓、塔盾、日轮徽记池中选出不同的两件，再由玩家选一件；附赠金币只发一次 |
| 二层宝藏主题的开放宝箱支路 | 改为一次性事件，从9个事件中固定抽取一个；不再额外发原宝箱物品与金币 |
| 二层商店主题的治疗支路 | 改为一次性休息点：恢复40HP，或攻击+3、防御+1 |
| 商店第三格 | 药剂或生命吊坠，替代原本充足的铜钥匙商品；前两格仍是攻击、防御商品 |

旅人换钥匙事件定义保留并通过结算测试，但不投放到钥匙足额保障的两层地图。没有新增第五条奖励支路。生命预算与经济已发生主题差异，需要继续试玩；设计文档原第9节金币账本仅适用于第2版配方。

## 领取与预览

- 装备和遗物无槽位，所有副本叠加，获得即生效。行囊按同名数量合并，显示图标、类型、阶级、效果和总击杀回血 / 金币加成。
- 普通箱、金币、钥匙仍自动拾取；选择箱、事件和休息点必须选定。取消后可以走过奖励格，回来再选；候选和未选事件不会变化。
- 药剂显示实际恢复和溢出量，确认才消耗。满血时不自动弹选择、不消耗；需要时点击当前药剂格或重新进入。
- 商人本局只出售一件。商品按钮展示价格，预览展示购买后的余额、生命与最终攻防；金币遗物造成的攻击下降已计入。满血时纯治疗商品禁用。
- 同时持有黄金剑与商王印记，100金币提供额外6攻；42金币购买淬钢刃后余额58、金币攻击剩3，最终净攻击增加4。
- 战斗显示实际受伤、击杀恢复及战中最低生命；守卫后方的箱子奖励单独列出，尚未拾取的物品不加入战斗计算。
- 事件生命成本至少保留1HP，资金不足不扣钱；物品未知或效果无效不删除实体、不发部分奖励。

## 代码与配置

| 文件 | 职责 |
| --- | --- |
| `scripts/core/rewards.gd` | 无副作用的成本与奖励事务；地图预览与实际发奖共用 |
| `data/content.json` | 已有12装备、10遗物、10商品、10事件的效果和价格 |
| `data/reward_rules.json` | 两层版候选池、事件池、第三格商品池和休息选项 |
| `scripts/core/map_generator.gd` | 第3版奖励投放；第1 / 2版不应用新覆盖规则 |
| `scripts/core/map_engine.gd` | 药剂确认、奖励选择、事件、交易、资源与实体一次性提交 |
| `scripts/core/map_save.gd` | 新奖励实体与待选状态校验，兼容历史地图 |
| `scripts/ui/map_screen.gd`、`item_icon.gd`、`grid_board.gd` | 奖励详情、最终属性预览、行囊、地图标记与图标 |

`data/random_maps.json` 的地形配置格式仍是2；这与运行时生成器版本3是不同字段。地形编写脚本继续输出原基础配方，第3版再依据独立奖励配置覆盖可选支路。没有改固定成长守卫、钥匙预算或怪物属性。

## 存档与兼容

现有手工、第1版、第2版地图保留原奖励实体，未访问的第二层也按原版规则生成；所有版本采用新的药剂确认与商店预览行为，不重新生成地图。

新开的本局保存装备、遗物、商店、事件定义快照；读档使用该快照，新开局重新使用最新内容。存档中的具体奖励候选、休息选项和领取后的实体移除一起保存。此前没有快照的老局仍使用当前内容定义，本次没有改变这些既有物品的数值。该快照不冻结敌人定义。

## 验证与边界

Godot 4.5.1 的生产逻辑测试覆盖所有22件物品、全部20个事件选项、治疗上限、生命献祭、购买前后金币攻击、重复领取、候选续存、内容快照和新旧生成版本。另有真实界面测试及320 / 540 / 900宽度检查，结果见 [验证记录](VALIDATION.md)。

复现新增测试：

```powershell
godot --headless --path . --script tests/reward_test_runner.gd
godot --headless --path . --script tests/reward_ui_test_runner.gd
godot --path . --rendering-method gl_compatibility --script tests/reward_ui_test_runner.gd -- --capture
```

截图保存在 `build/verification/reward_*.png`；测试用独立文件，不读写玩家正式存档。
