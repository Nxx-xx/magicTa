营地 v3 已交付，继续使用冷青林缘、暖金灯火、灰蓝石材和旧金属的方向。塔内应是同一世界的室内空间：地面保持可走区域清晰，墙有石檐、立面和墙脚阴影，暖光来自具体灯具；遗迹采用克制的冷色符文，Boss 区域有可识别的建筑仪式感。角色与物件优先保留形状和动作可读性。不能仅靠全屏调色、提高分辨率或测试数量来宣布精修成功。

实际审查：正式地图已引用 tower_v01 墙地和物件，其 README 中“尚未接入”是历史状态。现有墙顶重复网格明显，墙地界面和实体缺接触阴影，灯具/挂旗资源尚未用于正式地图。营地老骑士与公主、死神的造型仍不统一。主角、13 种敌人和遗迹已有正式动画、原生分层与运行 manifest，详见 phase3/COMPLETION_FOLLOWUP.md，不能降级为静态图重做。

## 每阶段验收方法

1. 固定 seed 42、相同尺寸和镜头捕获改前/改后真实 Godot viewport，至少 320×640、390×700、540×960；同时看全图与近景。测试场景生成的高层截图必须标明是美术夹具，不冒充自然通关。
2. 实际看图：可走路面与墙区区分，门钥匙与上下楼标记、敌人档次、角色脚底和选框清楚；无新增遮挡、穿帮、墙地错位或大面积过亮。教学框与交互面板另由现有主 UI 回归覆盖。
3. 正常动画有帧变化；减少动效画面稳定；渲染不修改玩法状态。动画源与运行清单未涉及的内容保持哈希。
4. 执行与修改相关的既有回归。装饰不改变碰撞/地图数据；若未来必须移动实体或碰撞，增加可达性与门钥匙路线验证。
5. 微信资源预算以实际 ZIP 与构建报告计量。可编辑源文件与历史版保留在项目，staging 只排除经引用检查的非运行资产；禁止全面降画质或提高预算规避超限。
6. 先构建独立包并核对资源、文件哈希、平台脚本测试和压缩资源画面，再发布 current，旧包可回退。桌面渲染与导出成功均不等于微信模拟器/真机或手机性能通过。
